# Backend Harness (NestJS 11)

> 백엔드 코드 작성 및 수정 시 에이전트가 **반드시 준수해야 하는** 세부 지침 및 기술 스택입니다.

---

## 1. 코어 아키텍처 및 데이터베이스
- **모듈화:** `NestJS`를 기반으로 비즈니스 로직을 철저히 도메인 중심 모듈(예: `insurance/`, `calendar/`)로 분리하여 응집도를 높입니다.
- **데이터베이스 (PostgreSQL + Prisma):**
  - 개발 환경(Local): `prisma migrate dev`로 스키마를 동기화합니다.
  - 배포 환경(Staging/Prod): 데이터 유실 및 충돌 방지를 위해 반드시 `prisma migrate deploy`를 사용합니다.

## 2. 환경 변수 및 시크릿 관리
- **하드코딩 절대 금지:** JWT 시크릿, DB 커넥션, 외부 API 키 등 민감 정보는 모두 `.env`를 통해 관리합니다.
- **사전 검증 (Validation):** `@nestjs/config`와 **`Zod`** (또는 Joi)를 결합하여 서버 부트스트랩 단계에서 모든 환경 변수의 타입과 존재 여부를 엄격하게 검증합니다.

## 3. 인증(Auth) 및 인가(RBAC)
- **API 인증:** `Passport`와 `JWT` 전략을 기본으로 사용합니다.
- **Row-level 권한 통제:** Custom Guard 또는 Interceptor를 활용하여 **본인(또는 인가된 가족)의 데이터만 조회/수정**할 수 있도록 접근 권한을 철저하게 강제합니다.

## 4. 비동기 처리 및 큐(Queue) 안정성
- **작업 분리 (`BullMQ` + `Redis`):** OCR 파싱, Gemini API 연동, 대량 알림 발송 등 지연이 발생하는 무거운 작업은 백그라운드 큐로 오프로딩(Off-loading)합니다.
- **장애 복구 정책:**
  - 외부 API 타임아웃에 대비해 **재시도(Retry) 및 Backoff 전략**을 반드시 명시합니다.
  - 최종 실패 시 작업을 **DLQ(Dead Letter Queue)**로 이동시키고, 필요시 클라이언트(사용자)에게 실패 상태를 알립니다.
- **스케줄링:** 만기 체크, 크롤링 등 주기적인 배치 작업은 `@nestjs/schedule`(`@Cron`)을 사용합니다.

## 5. 핵심 비즈니스 로직 구현
- **파일 처리:** 증권/약관 문서 업로드는 `Multer`를 사용하여 안전하게 처리합니다.
- **AI 기반 파싱:** `Tesseract.js`로 텍스트를 추출하고, `Gemini API`를 활용하여 비정형 보험 약관을 구조화된 데이터로 자동 변환합니다.
- **알림 채널:** `Nodemailer`(이메일), `FCM`(웹푸시), `카카오 알림톡` 연동을 지원합니다.
- **실시간 소통:** 즉각적 피드백이 필요한 경우 `@nestjs/websockets`(`Socket.io`)를 통해 클라이언트와 실시간 상태를 동기화합니다.

## 6. 품질 보증 (QA): 테스트 및 문서화
- **엄격한 타입 정의 (`any` 지양):** 백엔드 코드 작성 시 `any` 타입 사용을 최대한 지양하고, 구체적인 DTO나 인터페이스를 정의하여 타입 안정성을 확보해야 합니다.
- **테스트 자동화:** NestJS의 DI 구조를 적극 활용하여, **보안(권한 체크) 및 핵심 비즈니스 로직에 대한 Unit Test(Jest)를 필수로 작성**합니다. 주요 API 시나리오는 E2E Test(Supertest)로 검증합니다.
- **API 스펙 문서화:** 프론트엔드와의 명확한 인터페이스 공유(계약)를 위해 `@nestjs/swagger`를 도입, DTO 기반의 API 문서를 항상 최신으로 유지합니다.

## 7. 에러 핸들링 및 로깅
- **Global Exception Filter:** 모든 에러 응답은 `{ success: false, error: { code, message } }` 포맷으로 통일하여 클라이언트가 예측 가능하게 만듭니다. 내부 스택 트레이스는 절대 응답에 포함하지 않습니다.
- **데이터 마스킹:** 로그 시스템에 주민등록번호, 증권번호, 개인 연락처 등 민감 정보가 기록되지 않도록 철저히 마스킹 처리합니다.
