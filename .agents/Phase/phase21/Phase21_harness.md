# Phase 21: 프론트엔드 전수 Mock/더미 데이터 정리 및 실데이터 연동 무결성 검증 (Frontend Mock & Dummy Cleanup)

## 📌 목표 및 개요
프로젝트 프론트엔드(`apps/web/src`) 전역에 남아있는 레거시 Mock, 임시 더미(Dummy) 폴백, 테스트용 하드코딩 데이터를 전수 점검하고 정리하여, 모든 사용자 플로우가 실제 백엔드 API 및 실제 사용자 데이터와 안정적으로 연동되도록 무결성을 확보합니다.

1. **인증 및 소셜 로그인 플로우 내 잔여 더미/임시 코드 완전 제거**:
   - `OAuthCallbackPage.tsx`, `Login.tsx` 등에서 사용자 정보 조회 실패 시 임시 더미 계정(`social_user`, `social@boim.internal`)으로 자동 로그인되던 비정상 폴백을 전면 제거하고, 정식 에러 메시지 안내 및 안전한 로그인 재시도 UI로 전환합니다.
   - 브라우저 스토리지 잔류 키(`temp_token`) 및 미사용 임시 state(`mock_state`)를 완전히 정리합니다.
2. **문서/증권 분석 API 및 업로더 잔여 Mock 네이밍 정제**:
   - `useDocumentQueries.ts`의 `mockData` 변수명 및 타입을 정식 규격 명칭(`presetData`, `sampleData`)으로 정제합니다.
   - `PolicyDocumentUploader.tsx`의 가상/모의 표기를 서비스 온보딩용 정식 '샘플 증권' 안내로 다듬습니다.
3. **프론트엔드 전역 하드코딩/더미 데이터 전수 감사(Audit) 및 실데이터 바인딩 무결성 검증**:
   - 캘린더, 대시보드, 내 보험, 보험료 분석 차트, AI 진단 리포트, 알림, 설정 패널 등 핵심 도메인 전반의 실데이터 바인딩 및 빈 상태(Empty State) / 에러 상태(Error State) 대응을 점검합니다.
   - 랜딩 페이지의 홍보용 프리뷰 카드와 실제 서비스 데이터 계층의 경계를 명확히 문서화/주석화합니다.
4. **품질 및 빌드 무결성 유지**:
   - 프론트엔드(Vitest) 및 백엔드(Jest) 전사 테스트 100% 통과 유지
   - TypeScript 컴파일 및 린트 0 에러 보장
